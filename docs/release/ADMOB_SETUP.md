# Як підключити справжню рекламу AdMob (інструкція для Власника)

> Простими словами: зараз у застосунку **тестова реклама** Google (безпечна, грошей не приносить). Щоб реклама приносила дохід, треба один раз створити застосунок і два рекламні блоки в AdMob і вписати три числові коди у файл на комп'ютері. Нічого програмувати не потрібно. Усі дії в AdMob виконує лише Власник (розд. 3.2 конституції). Реальні коди **не** надсилай у чат і не додавай у git.

## Що працює за замовчуванням
- **Debug-збірка** (для перевірок і телефона) завжди має тестові коди Google. Файл `admob.properties` вона ігнорує.
- **Release без файла `admob.properties`** збирається з тестовими кодами і показує в консолі помітне попередження («УВАГА (AdMob)…»).
- **Release з `-Pproduction=true`** збирається ЛИШЕ з вашими справжніми кодами. Якщо файла немає, він неповний або в ньому тестові коди, збірка зупиняється з поясненням. Це захист від помилкового випуску без реклами.

## Крок 1. Створи застосунок і блоки в AdMob (у браузері, акаунт AdMob)
Назви кнопок у консолі AdMob можуть трохи відрізнятися; шукай схожі.
1. Відкрий https://admob.google.com → «Застосунки» (Apps) → «Додати застосунок» (Add app) → платформа **Android**.
2. Якщо застосунок ще не опублікований у Google Play, вибери «Ні» (No) на питання про публікацію. Назва: Anti PDF.
3. Скопіюй **Ідентифікатор застосунку** (App ID). Має вигляд `ca-app-pub-1234567890123456~1234567890` (посередині знак **~**).
4. Відкрий застосунок → «Рекламні блоки» (Ad units) → «Додати рекламний блок» → тип **Банер** (Banner). Назва довільна (наприклад, «Банер»). Скопіюй **Ідентифікатор рекламного блоку** (Ad unit ID). Вигляд: `ca-app-pub-1234567890123456/1234567890` (посередині знак **/**).
5. Так само створи блок типу **Interstitial** (повноекранний). Скопіюй його ідентифікатор.

У тебе має бути три коди: застосунок (з ~), банер (з /), interstitial (з /). Перша частина до ~ або / у всіх трьох однакова.

## Крок 2. Створи файл `admob.properties` (PowerShell)
Відкрий PowerShell у папці проєкту (де лежить `gradlew.bat`) і виконай:

```powershell
Copy-Item admob.properties.example admob.properties
notepad admob.properties
```

У Блокноті впиши після знака `=` три коди (без пробілів і лапок), збережи й закрий:

```
admob.appId=сюди код застосунку (з ~)
admob.bannerAdUnitId=сюди код банера (з /)
admob.interstitialAdUnitId=сюди код interstitial (з /)
```

Файл `admob.properties` у `.gitignore`: він лишається лише на цьому комп'ютері й у git не потрапляє. Не пересилай його нікому.

## Крок 3. Збери release
У тому самому PowerShell (потрібен JDK 21 і, для підписаного файла, `keystore.properties`, див. `docs/store/RELEASE_SIGNING.md`):

```powershell
$env:JAVA_HOME = "C:\Users\cocro\.jdks\jbr-21.0.11"
.\gradlew.bat :app:bundleRelease -Pproduction=true
```

Успіх: у кінці `BUILD SUCCESSFUL` і рядок `AdMob: маніфест release OK (бойовий Application ID)`. Готовий файл: `app\build\outputs\bundle\release\app-release.aab`.
Якщо збірка зупинилась з повідомленням, що починається з «AdMob:», у ньому написано, що виправити (немає файла, не вистачає рядка, переплутано `~` і `/`, у файлі тестові коди).

## Чого НЕ робити
- Не вставляй справжні коди в код, документи, чат або листи.
- Не клацай по своїй справжній рекламі під час перевірок: це порушує правила AdMob. Для перевірок використовуй debug (тестові коди).
- Після зміни кодів новий блок може починати показувати рекламу не одразу (AdMob потрібен час).

## Для розробника (довідка)
- Логіка: кореневий `build.gradle.kts` (блок «AdMob ID»), `core-ads/build.gradle.kts` (BuildConfig `ADMOB_BANNER_AD_UNIT_ID`, `ADMOB_INTERSTITIAL_AD_UNIT_ID`, `ADMOB_USING_TEST_IDS`), `app/build.gradle.kts` (manifest placeholder `admobAppId`, задача `verifyAdmob<Variant>Manifest`).
- Перевірки: `:core-ads:testDebugUnitTest` (`AdIdsConfigTest`: debug тільки тестові ID); `:app:verifyAdmobDebugManifest` (у склеєному маніфесті debug лише тестовий Application ID; входить у `:app:check`); `:app:verifyAdmobReleaseManifest` після `assembleRelease`/`bundleRelease`.
- Сценарії (перевірено 2026-11-18, див. `project_log.md`): без файла release тестовий + попередження; `-Pproduction=true` без файла падає; неповний або хибний файл падає завжди; файл із тестовими ID + `-Pproduction=true` падає; debug завжди тестовий.
