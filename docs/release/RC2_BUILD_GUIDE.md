# Збірка підписаного AAB для RC2 (версія 1.0.1): інструкція для власника

> Простими словами, Windows і PowerShell. **Один крок за раз:** зроби крок, надішли координатору відповідь з рядка «Що надіслати», і лише тоді переходь далі. Пароль і файл ключа нікому не надсилай і в чат не вставляй. Агенти ключ не бачили й не бачитимуть.
>
> Чому саме так: спосіб підпису описано в `docs/store/RELEASE_SIGNING.md` (локальний файл `keystore.properties` у корені проєкту, команда `./gradlew :app:bundleRelease`), а RC1 за `docs/release/RELEASE_CANDIDATE_2026-11-17.md` зібрано тією ж командою. **Чого в документах НЕМАЄ:** у якій саме папці й ким RC1 збирали. Тому крок 2 починається з перевірки, що `keystore.properties` лежить у тій папці, де ти збираєш (див. нижче). Нічого іншого я не вигадував.

## Що буде в результаті
Файл `app\build\outputs\bundle\release\app-release.aab`, версія **1.0.1** (код версії **2**), підписаний твоїм ключем завантаження (upload key). Його координатор завантажить у закритий трек «Alpha» в Play Console лише з твого дозволу.

Реклама в цій збірці **тестова** (файлу `admob.properties` з бойовими кодами ще немає). Для закритого тесту це свідомо прийнято. Під час збірки з'явиться велике попередження «УВАГА (AdMob)». Це нормально. Прапорець `-Pproduction=true` **не використовуй**.

## Крок 1. Оновити локальну папку проєкту до `main`
Виконувати лише **після** того, як координатор напише, що гілку `release/rc2` злито в `main` (після незалежної перевірки QA).

```powershell
cd C:\Users\cocro\AndroidStudioProjects\pdf-reader-android
git fetch
git checkout main
git pull
git log --oneline -3
git status --short
```
Якщо твоя папка проєкту інша, перейди в неї (там лежить файл `gradlew.bat`).

**Що надіслати у відповідь:** три рядки з `git log --oneline -3` і те, чи `git status --short` вивів щось (порожньо — добре). Перший рядок має бути комітом злиття `release/rc2`, його номер скаже координатор.

Якщо `git pull` пише про конфлікт або про незбережені зміни — **зупинись** і надішли цей текст координатору, нічого не видаляй.

## Крок 2. Зібрати підписаний release AAB
2.1. Переконайся, що файл ключових налаштувань на місці (команда лише повертає True або False, вміст не показує):

```powershell
Test-Path .\keystore.properties
```
**Має бути `True`.** Якщо `False`: або ти в іншій папці, ніж та, де збирав RC1, або файл лежить деінде. Тоді **не збирай** (вийде непідписаний файл) і напиши координатору «False».
Якщо `keystore.properties` ще не створено, дивись `docs/store/RELEASE_SIGNING.md` (кроки 1–2; ключ завантаження вже має бути з RC1, новий не створюй без координатора).
**Увага:** якщо у файлі `storeFile` вказує на неіснуючий шлях або якогось рядка бракує, збірка НЕ впаде, а вийде **непідписаною**. Як це розпізнати, написано в кроці 3.3.

2.2. Перевір Java (потрібен JDK 21):

```powershell
java -version
```
У першому рядку має бути версія `21...`. Якщо ні, встанови змінну `JAVA_HOME` на ваш JDK 21 у цьому вікні PowerShell (шлях до папки JDK ти знаєш сам; я його не вгадую): `$env:JAVA_HOME = "<папка вашого JDK 21>"`. Якщо Gradle далі скаржиться на Java, надішли координатору цей рядок помилки.

2.3. Збірка:

```powershell
.\gradlew.bat :app:bundleRelease
```
Збірка триває кілька хвилин. Пароль ключа вводити **не треба**: Gradle бере дані з `keystore.properties` сам. Якщо раптом якась програма просить пароль, введи його **лише у своєму вікні PowerShell**, нікому не показуй.

Успіх: у кінці `BUILD SUCCESSFUL` і рядок `AdMob: маніфест release OK (тестовий Application ID)`.

**Що надіслати у відповідь:** слова «BUILD SUCCESSFUL» (або останні 15 рядків, якщо була помилка). Паролі в цих рядках не з'являються; якщо помітиш щось схоже на пароль, не надсилай цей рядок.

## Крок 3. Перевірити версію й підпис (без розкриття ключа)
Ці команди лише читають готовий файл. Ключ вони не відкривають.

3.1. Розмір, час створення і контрольна сума файла:
```powershell
$aab = ".\app\build\outputs\bundle\release\app-release.aab"
Get-Item $aab | Select-Object Name, Length, LastWriteTime
(Get-FileHash $aab -Algorithm SHA256).Hash
```

3.2. Версія (має бути код версії 2 і назва версії 1.0.1):
```powershell
Select-String -Path ".\app\build\intermediates\merged_manifests\release\processReleaseManifest\AndroidManifest.xml" -Pattern 'versionCode|versionName'
```
Очікуєш два рядки: `android:versionCode="2"` і `android:versionName="1.0.1"`.

3.3. Файл справді підписаний. Команди `jarsigner` і `keytool` входять у JDK 21 (якщо PowerShell їх не знаходить, запускай з папки `bin` твого JDK 21, наприклад `& "$env:JAVA_HOMEin\jarsigner.exe" ...`):
```powershell
jarsigner -verify $aab
```
- **Підписаний файл:** рядок `jar verified.` (можливе попередження, що сертифікат самопідписаний: для ключа завантаження це нормально).
- **НЕпідписаний файл:** `jarsigner` пише `no manifest.` Це ознака, що збірка вийшла непідписаною (див. крок 2.1: перевір `keystore.properties` і чи існує файл, на який вказує `storeFile`). Не завантажувати, повідомити координатора.

3.4. Відбиток сертифіката (SHA-256). Це відкритий «відбиток пальця» ключа, а не сам ключ:
```powershell
keytool -printcert -jarfile $aab | Select-String "SHA256|Owner"
```
- **Підписаний файл:** рядки `Owner:` і `SHA256:`.
- **НЕпідписаний файл:** `keytool` пише `Not a signed jar file`: те саме, що в 3.3, збірка непідписана.

Порівняй рядок `SHA256:` з відбитком ключа завантаження в Play Console: **Налаштування застосунку → Підпис застосунку (App signing) → «Сертифікат ключа завантаження» (Upload key certificate) → SHA-256**. Вони мають збігатися повністю. (Назви пунктів меню в консолі можуть відрізнятися: шукай слова «App signing» і «Upload key certificate».)

Якщо відбитки різні, **не завантажуй**: це інший ключ, Google відхилить файл.

**Що надіслати у відповідь:** (а) вивід команд 3.1 і 3.2; (б) слова `jar verified.` або `no manifest.`; (в) рядок `SHA256:` з 3.4 **і** «збігається» або «не збігається» з Play Console. Відбиток сертифіката не секретний, його можна надсилати.

## Крок 4. Повідомити координатора, що AAB готовий
Надішли координатору одним повідомленням:
- повний шлях до файла: `…\app\build\outputs\bundle\release\app-release.aab`;
- розмір у байтах (з 3.1; орієнтир ≈ 16,3 МБ = ≈ 16 320 000 байт; дуже відмінний розмір — привід перевірити);
- SHA-256 файла (з 3.1, перші 16 символів досить).

**Завантаження в Play Console робить координатор у браузері, лише з твого прямого дозволу.** Сам нічого не завантажуй, поки не домовились (кроки консолі: `docs/release/RC2_CHECKLIST.md`).

## Якщо щось пішло не так
- `BUILD FAILED` — надішли останні 15 рядків виводу. Нічого не видаляй.
- Файл вийшов непідписаним (`no manifest.` / `Not a signed jar file`) — `keystore.properties` не в тій папці або `storeFile` вказує на неіснуючий шлях (див. 2.1).
- Не збігається відбиток — не завантажувати; координатор разом із тобою розбереться, який ключ використано.
- Версія в 3.2 не `2` / `1.0.1` — ти зібрав не з `main` після злиття; повтори крок 1.
