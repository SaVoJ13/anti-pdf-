# Перевірка 16 KB (нативні бібліотеки), 2026-11-18

Гілка `fix/stage1-ads-16kb` (AdMob 25.5.0), release без `admob.properties` (тестові ID), JDK 21, непідписаний (ключ власника не використовувався).

## Результат
У release AAB і APK **жодної нативної бібліотеки (`.so`) немає**, тому нічого перевіряти на `p_align >= 0x4000` (ELF LOAD) і вирівнювання `.so` у zip не потрібно.

| Перевірка | Команда | Результат |
|---|---|---|
| `.so` в AAB (`app-release.aab`, 16 320 218 байт) | `unzip -l app-release.aab` і пошук `.so` та `/lib/` | 0 збігів (єдиний збіг шаблону `.bin` це `base/root/DebugProbesKt.bin`, не ELF) |
| Верхні каталоги AAB | `unzip -Z1 app-release.aab`, підрахунок за двома першими сегментами шляху | `base/res` 972, `base/assets` 120, `base/root` 111, `base/dex` 1, метадані; каталогу `base/lib` немає |
| `.so` в APK (`app-release-unsigned.apk`, 17 397 376 байт, 1208 файлів) | `unzip -l` і пошук `.so` та `lib/` | 0 збігів |
| zip-вирівнювання APK | `zipalign -c -P 16 -v 4 app-release-unsigned.apk` (build-tools 36.0.0) | `Verification successful`, код виходу 0 |
| Таблиця «бібліотека / архітектура / p_align» | `llvm-readelf -l` (NDK 30.0.16248370 є в середовищі) | порожня: перевіряти нічого |

## Пояснення
- Залежності, які могли б нести нативний код (PdfBox-Android, androidx.pdf, ML Kit Document Scanner, play-services-ads, UMP), `.so` у пакет не кладуть: сканер і реклама працюють через Google Play services на пристрої. Це висновок із фактичного вмісту пакета, а не з документації залежностей.
- Висновок збігається із записом у `CURRENT_STATE.md` (QA №2, 2026-11-17) і лишається вірним після оновлення AdMob до 25.5.0.

## Обмеження
- `bundletool build-apks` не запускався: у проєкті й SDK його немає (знайдено лише сторонній `bundletool-1.17.2.jar` в іншому проєкті, не використано), а `.so` немає, тож перевірка архітектурних split-APK не дала б нової інформації. APK з Gradle (`assembleRelease`) перевірено `zipalign`.
- Дії Власника не потрібні. Після кожного оновлення залежностей повторювати пошук `.so` в AAB; якщо з'являться, перевірити `llvm-readelf -l` і `zipalign -c -P 16`.
