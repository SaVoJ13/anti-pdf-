# Anti PDF — критерії приймання редизайну

> Цей документ перетворює дизайн на перевірні умови. Позначка «пройдено» можлива лише за фактичним доказом. Неперевірене позначається **НЕ ПЕРЕВІРЕНО**.

## 1. Наскрізні сценарії

| ID | Сценарій | Критерій успіху |
|---|---|---|
| AC-01 | Перший запуск | 3 сторінки онбордингу читаються при 150% шрифті; Пропустити й Почати ведуть у Бібліотеку; UMP не перекривається онбордингом |
| AC-02 | Відкрити PDF | З Бібліотеки файл вибирається через SAF, відкривається в Читачі, системний Назад повертає без втрати стану |
| AC-03 | Пошук недавніх | Результат оновлюється, no-results state зрозумілий, закриття пошуку повертає повний список |
| AC-04 | Редагувати й зберегти | Текст додається, незбережений стан видимий, копія зберігається, оригінал не пошкоджено |
| AC-05 | Скасувати зміни | Вихід зі змінами дає три зрозумілі варіанти й виконує обраний без прихованої втрати |
| AC-06 | Форма | Поля доступні послідовно, обов’язкові позначені не лише кольором, значення зберігаються |
| AC-07 | Інструмент сторінок | Інструмент знаходиться з вкладки й читача; входи/параметри/збереження мають однаковий каркас |
| AC-08 | Результат операції | Є Відкрити, Поділитися, Готово; реклама не з’являється до завершення збереження |
| AC-09 | Захищений/непридатний PDF | Помилка пояснює стан, секрет не логується, читання доступне там, де редагування заборонене |
| AC-10 | Відновлення | Поворот/перезапуск процесу не запускає операцію двічі й не створює непідтверджений файл |

## 2. Візуальна й адаптивна матриця

Перевіряються ключові екрани: Онбординг, Бібліотека (list/empty/search), Інструменти, робоча операція, Читач read/edit, Форми, Організатор, Налаштування, Ліцензії.

| Вимір | Значення |
|---|---|
| Android | 9 (API 28), 11 (API 30), актуальний на Galaxy S24 Ultra |
| Ширина | 320, 360, 411 dp; 600+ dp; 840+ dp для адаптивних ресурсів |
| Орієнтація | портрет, ландшафт |
| Тема | світла, темна, системна; dynamic color on/off де підтримано |
| Шрифт | 100%, 130%, 150%; основні потоки 200% |
| Навігація | жести, 3 кнопки |
| Системні області | звичайна status bar, виріз, gesture inset, відкрита клавіатура |

Умови:

- немає обрізаних заголовків, головних кнопок або тексту помилок;
- немає горизонтального прокручування екрана; виняток — документ або явно прокручувана галерея;
- toolbar, bottom bar, sheet і snackbar не заходять під системні області;
- клавіатура не перекриває активне поле й головну дію;
- поворот не змінює вибраний файл, параметри або режим без причини.

## 4. Повнота функцій

Після редизайну мають залишитися доступними:

- Library: open, recent history, search, filter/sort, favorite, clear history;
- appearance/legal/privacy: theme, dynamic colors, consent/privacy, OSS licenses;
- reader: read, page navigation, search, favorite, save/save copy, share, print, details;
- markup: text, freehand, ✓/✗, image, signature, select/edit/delete, undo/redo;
- forms: виявлення, навігація, заповнення, збереження підтриманих AcroForm-полів;
- pages/tools: blank, scan, organize, merge, split, rotate, delete, images-to-PDF, watermark, page numbers, compress;
- reader add/actions: add page, add image, insert file та всі фактично підтримані дії з карти функцій.

Втрата маршруту до будь-якої функції — блокуючий дефект, навіть якщо сама реалізація лишилася в коді.

## 5. Помилки, прогрес і безпечне збереження

- тривала дія має прогрес і захист від повторного запуску;
- cancel/back не лишає напівготовий результат у видимому каталозі;
- помилка не знищує оригінал і прямо це повідомляє;
- ім’я вихідного файла можна виправити до збереження;
- помилки SAF, нестачі пам’яті, пароля й пошкодженого PDF мають різні корисні повідомлення;
- паролі, URI приватних файлів і вміст документів не потрапляють у логи або screenshots репозиторію.

## 6. Реклама та згода

- banner є лише у дозволених списках/інструментах і не перекриває навігацію;
- читач, редактор, форми, організатор і процес збереження не містять banner;
- interstitial можливий лише після успішної завершеної дії;
- відмова/відсутність реклами не блокує функції;
- зміна згоди доступна в Налаштуваннях;
- перший запуск коректно координує Онбординг і UMP.

## 7. Регресія й докази

Для кожного етапу потрібні:

1. зелена обов’язкова Gradle-команда на JDK 21;
2. кількість тестів з XML-звітів, а не з консольного припущення;
3. чекліст змінених сценаріїв на Galaxy S24 Ultra;
4. Android 9/11 emulator evidence для системних відступів;
5. окремий QA-субагент, який не є автором;
6. запис у `docs/project_log.md` з усім неперевіреним як **НЕ ПЕРЕВІРЕНО**.

## 8. Блокуючі дефекти

- падіння, ANR, пошкодження або втрата документа;
- недоступна наявна функція;
- головна дія невидима/недоступна при 150% шрифті;
- читання або редагування перекрито рекламою;
- системна панель або клавіатура перекриває критичний UI;
- секрет/пароль/особистий вміст у логах;
- автор самостійно поставив `QA Verified`.
