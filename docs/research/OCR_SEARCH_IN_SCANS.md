# Дослідження: OCR і пошук у сканах

> Тільки дослідження. Код не змінювався, нічого не впроваджено. Статус: готово до QA (перевірка документа), `QA Verified` немає. База: `main` `c65e367`.
> Рішення Власника (2026-11-24, `docs/governance/DECISIONS.md:105`): OCR лише **після релізу (production)**. Перед початком обов'язково: розмір застосунку, 16 KB для `.so`, Data safety, `THIRD_PARTY.md`; ролі «PDF-ядро» й «Монетизація і Google Play», окремий QA.
> Позначки: підтверджено читанням коду/документів репозиторію; «ЗА САЙТОМ GOOGLE» = знайдено веб-пошуком 2026-11-25, сторінку повністю не читав, перепровірити; «НЕ ПЕРЕВІРЕНО» = не підтверджено.

## 1. Проблема простими словами
Скан із камери або зображення в PDF це картинки без тексту. Пошук у читалці (`androidx.pdf`, `ReaderActivity.kt:268-290`) шукає лише в текстовому шарі, тому в сканах нічого не знаходить (`FEATURE_AUDIT.md` R2, §5.2). OCR перетворює картинку на текст, щоб шукати, виділяти й копіювати.

## 2. Що є в проєкті зараз (підтверджено)
- Розпізнавання тексту в коді немає. ML Kit лише `play-services-mlkit-document-scanner:16.0.0-beta1` (`app/build.gradle.kts:115`): сканер працює через Google Play services на пристрої.
- Текст сторінки з PDF: `PDFTextStripper` із PdfBox (використовується в тестах `core-pdf`); `androidx.pdf` текст через API не віддає (`FEATURE_AUDIT.md:165`).
- Room 2.6.1 (`app/build.gradle.kts:110-112`), база `AppDatabase.java` із таблицею `RecentDocument`: є де додати індекс, але зараз там лише «Останні».
- Нативних бібліотек у релізі немає: 0 `.so` в AAB (16 320 218 байт) і APK (17 397 376 байт) станом на 2026-11-18 (`docs/release/ELF_16KB_CHECK_2026-11-18.md`). Висновок для OCR: будь-який варіант із `.so` змінить цей добрий стан.
- Мінімальна Android 9 (`minSdk = 28`), R8 увімкнено (`isMinifyEnabled = true`).
- Data safety вже розкриває ML Kit (сканер): Device or other IDs, Diagnostics, Other app performance data, обов'язкові (`docs/store/DATA_SAFETY.md:44,51`).

## 3. Підтримувані мови: головна проблема
Потрібні: uk, en, de, es, ru (мови інтерфейсу), тобто **кирилиця + латиниця**.
- ML Kit Text Recognition v2: скрипти Latin, Chinese, Devanagari, Japanese, Korean (ЗА САЙТОМ GOOGLE: `developers.google.com/ml-kit/vision/text-recognition/v2/languages`). **Кирилиці в списку немає.** Тобто en, de, es розпізнаються (латиниця, діакритика НЕ ПЕРЕВІРЕНО на якість), а **uk і ru не підтримуються** офіційно. Це збігається із записом `FEATURE_AUDIT.md:165`. Остаточно перечитати сторінку мов перед рішенням.
- Tesseract: підтримує кирилицю (мовні файли `ukr`, `rus`, `eng`, `deu`, `spa`); НЕ ПЕРЕВІРЕНО по версіях і якості. Кожна мова це окремий файл даних (розміри НЕ ПЕРЕВІРЕНО).
- Висновок: для власника українськомовного продукту ML Kit без кирилиці закриває лише частину користувачів.

## 4. Варіанти

### Варіант A. ML Kit Text Recognition v2, модель у складі застосунку (bundled)
- Артефакти (ЗА САЙТОМ GOOGLE): `com.google.mlkit:text-recognition` (Latin), додатки по скриптах.
- Розмір (ЗА САЙТОМ GOOGLE, японська сторінка, англійська цих цифр не показала): приблизно 4 МБ на скрипт на архітектуру. AAB ділиться на архітектури, тож для користувача менше, ніж для універсального APK. **НЕ ПЕРЕВІРЕНО** точно.
- 16 KB: модель постачається разом із **нативним кодом** (ML Kit vision), тобто в AAB з'являться `.so`; їхнє вирівнювання 16 KB **НЕ ПЕРЕВІРЕНО**. Це порушило б сьогоднішній стан «0 `.so`».
- Data safety: вбудована модель працює на пристрої без мережі. Чи збирає ML Kit у цьому режимі діагностику: **НЕ ПЕРЕВІРЕНО** (сторінка `developers.google.com/ml-kit/android-data-disclosure`).
- Офлайн: повністю.
- Кирилиця: ні (п. 3).

### Варіант B. ML Kit Text Recognition v2 через Google Play services (unbundled)
- Артефакти (ЗА САЙТОМ GOOGLE): `com.google.android.gms:play-services-mlkit-text-recognition` та варіанти по скриптах.
- Розмір (ЗА САЙТОМ GOOGLE): приблизно 260 КБ на архітектуру в застосунку; модель завантажує Google Play services. **НЕ ПЕРЕВІРЕНО** точно.
- 16 KB: модель і нативний код живуть у Play services, у нашому пакеті `.so` не очікується (так само, як зараз зі сканером, `ELF_16KB_CHECK_2026-11-18.md`:17). Перевірити фактичним AAB.
- Data safety: так само, як сканер: працює через Play services; діагностику збирає ML Kit. Нових типів даних, імовірно, не з'явиться, бо ті самі SDK Google вже розкриті; **НЕ ПЕРЕВІРЕНО** для Text Recognition окремо. Є опис завантаження моделі з мережі при першому використанні: **НЕ ПЕРЕВІРЕНО** потреба в декларації та тексті для Власника.
- Офлайн: після завантаження моделі так; перший раз без інтернету може не спрацювати (**НЕ ПЕРЕВІРЕНО**, є механізм попереднього завантаження через маніфест, **НЕ ПЕРЕВІРЕНО**).
- Залежить від Play services (на пристроях без них не працює; для Google Play-аудиторії зазвичай не проблема).
- Кирилиця: ні (п. 3).

### Варіант C. Tesseract (Android-обгортка, напр. tess-two / Tesseract4Android)
- Версії й ліцензії обгорток: **НЕ ПЕРЕВІРЕНО** (Tesseract сам Apache-2.0, обгортки перевірити окремо).
- Нативні `.so` для кожної архітектури: велике збільшення розміру (кількість МБ, **НЕ ПЕРЕВІРЕНО**) та **пряма вимога перевірки 16 KB** (правило Google для оновлень застосунків; у `PUBLICATION_READINESS_2026-11-16.md:33` позначено «для оновлень діє вимога з 2027-02-01», перевірити поточний текст).
- Data safety: нічого не передається, нових SDK Google немає: найчистіший варіант за приватністю.
- Офлайн: повністю; мовні файли треба вкласти в застосунок (або завантажувати: тоді з'являється мережа, чого зараз немає для даних користувача).
- Кирилиця: так (мови `ukr`, `rus`).
- Якість і швидкість на сканах телефона: **НЕ ПЕРЕВІРЕНО**, зазвичай повільніше й гірше за ML Kit без попередньої обробки зображення.

## 5. Як зберігати розпізнаний текст
1. **Невидимий текстовий шар у PDF** (рекомендовано як ціль): PdfBox дописує на сторінку невидимий текст (режим відображення 3, без заливки) у позиціях слів. Тоді пошук `androidx.pdf` у читалці, виділення й копіювання працюватимуть без змін, файл переносний (у Chrome, Adobe теж шукається). Потрібен шрифт із кирилицею: Roboto/Liberation Sans уже в проєкті (`ARCHITECT_DECISION_2026-11-07.md`, `THIRD_PARTY.md:47`). Ризики: збільшує файл, змінює оригінал (робити лише в **новій копії**), зашифровані файли (потрібен пароль, див. `PASSWORD_PROTECT.md`), якість розміщення слів над картинкою. Раніше проєкт уже вивчав координати сторінок (`docs/research/SPIKE_PAGE_COORDS.md`): корисно для перерахунку координат ML Kit у координати PDF.
2. **Індекс у Room** (для пошуку по всій бібліотеці): нова таблиця (документ, сторінка, текст), міграція бази. Текст лишається на пристрої. Окремо від PDF, швидкий пошук між файлами. Недолік: не переноситься з файлом. Для тексту з PDF, що вже має текстовий шар, індекс можна наповнювати через `PDFTextStripper`, тож пошук по бібліотеці працює і для звичайних PDF.
3. Рекомендація: **обидва, поетапно**: (а) індекс у Room лише зі сторінок, де текст уже є або розпізнаний; (б) запис шару в нову копію PDF за бажанням користувача.

## 6. Пошук у бібліотеці
- Зараз екран бібліотеки показує «Останні» (`RecentDocument`); повнотекстового пошуку між файлами немає (НЕ ПЕРЕВІРЕНО окремо, у `FEATURE_AUDIT.md` не зафіксовано).
- Для пошуку по всіх файлах потрібні: фонове індексування (WorkManager уже в графі залежностей, `THIRD_PARTY.md:48`), прогрес і скасування, повага до заряду й пам'яті, FTS у Room (`@Fts4`, **НЕ ПЕРЕВІРЕНО** у проєкті), видалення індексу, коли файл зник.
- Доступ до файлів: застосунок працює через системний вибір, постійних дозволів на всі файли немає. Індексувати можна лише відкриті раніше (збережені URI): обмеження, на яке Власнику треба звернути увагу.

## 8. Ризики
1. **Кирилиця не підтримана ML Kit**: ключовий ризик для української аудиторії; без вибору C OCR для uk/ru не працює.
2. 16 KB: у варіантах A і C з'являються `.so`; Google вимагає вирівнювання (вимога для оновлень діє з 2027-02-01 за `PUBLICATION_READINESS_2026-11-16.md:33`, перепровірити).
3. Data safety і політика: зміна декларації після публікації це ризик відхилення; потрібна роль «Монетизація і Google Play».
4. Розмір застосунку (A, C) і час/заряд на пакетну обробку; великі скани (`LARGE_FILES_REPORT.md`).
5. Якість OCR на нерівних фото, табличках, рукописному тексті.
6. Невидимий шар змінює файл користувача: лише нова копія, чесне попередження.
7. Залежність від Play services (B) і від першого завантаження моделі.

## 9. Рекомендація
1. Не починати до production (рішення Власника).
2. Перше завдання після релізу: **вимірювальний прототип без зміни основної збірки** (окрема гілка): ML Kit Latin (B) на реальних сканах en/de/es; перевірка, що кирилицю справді не розпізнає; розмір AAB, наявність `.so`, 16 KB (`bundletool`, як в `ELF_16KB_CHECK_2026-11-18.md`).
3. Якщо uk/ru обов'язкові: порівняти з Tesseract (C) на тих самих сканах і вирішити за якістю й ціною розміру; якщо ні, почати з B (малий розмір, без `.so` у пакеті) лише для латиниці.
4. Спершу робити індекс Room для пошуку (швидка цінність), потім шар у копії PDF.
5. Рішення, потрібні від Власника: чи обов'язкові uk/ru на старті; чи допустимо завантаження моделі через Play services; чи допустимий приріст розміру.
