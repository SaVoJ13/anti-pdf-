## Висновки (коротко)

1. **Найбезпечніший шлях для закритого комерційного застосунку з рекламою:** вбудовані платформні засоби (`PdfRenderer` / Jetpack `androidx.pdf`) + **Apache-2.0 бібліотеки** (PDFium-збірки, PDFBox-Android) для операцій над файлами. Ліцензійних платежів 0.
2. **Несумісні із закритим кодом без платної ліцензії:** **MuPDF (AGPL)**, **iText (AGPL)**. Для закритого продукту потрібна комерційна ліцензія («ціна за запитом»).
3. **Комерційні SDK** (Apryse, Foxit, Nutrient) — потужні, але ціна за запитом/тисячі $ на рік; для MVP, ймовірно, надмірно.
4. **Платформний PdfRenderer** нового покоління вміє пошук, виділення, анотації, форми, паролі, але потребує SDK Extension 13 (Android 11+ за одним зведенням, Android 12+ за іншим — **суперечність, НЕ ПЕРЕВІРЕНО**). Для minSdk нижче потрібен запасний шлях (PDFium-збірка).
5. **Google Play (за зведенням):** акаунт $25 одноразово; для **нових особистих** акаунтів — закрите тестування мінімум **12 тестувальників × 14 днів поспіль**; **організаційні** акаунти від цього звільнені; нові застосунки/оновлення мають націлюватись на **API 36** (термін 31.08.2026 уже минув); нативні `.so` мають підтримувати **16 KB page size**.
6. Для застосунку з рекламою в ЄС власник = «трейдер» за DSA → **адреса/контакти публічно** у картці. Це важливе рішення власника (юрособа/ФОП/віртуальна адреса).
7. **Анотації** слід писати стандартними PDF-анотаціями (Highlight/Underline/Ink/FreeText/Text), щоб їх бачили інші читачі. «Редагування наявного тексту», OCR — **не в MVP**.
8. **Назва**: перевірку знаків (Play, TMview, USPTO) я виконати не зміг — **НЕ ПЕРЕВІРЕНО**. «PDF Reader» — загальний описовий термін, знаку на нього, найімовірніше, не дадуть, але є безліч застосунків з такою назвою — **потрібна дистинктивна назва**.

## 3. Реклама

### 3.1 Варіанти
- **Google AdMob (рекомендовано для старту):** найпростіше, підтримка UMP (згода). Мінус: Advertising ID, мережевий трафік, розмір SDK (**НЕ ПЕРЕВІРЕНО**), вимагає `INTERNET`.
- **Альтернативи (AppLovin MAX, Unity Ads, Meta Audience Network, Яндекс/інші):** **не досліджував глибоко — НЕ ПЕРЕВІРЕНО**. Кожна додає свій SDK, ризик політик, більше даних у Data safety. Для MVP не рекомендую.

### 3.2 Політики Google Play щодо реклами [З ЗВЕДЕННЯ ПОШУКУ, джерело — Google Play/AdMob Policy; дата перевірки 2026-11-03]
- Interstitial **не** при запуску й **не** при виході; не після кожної дії; не одразу після іншого interstitial; не посеред читання/заповнення форми.
- Реклама не повинна заважати навігації; кнопки не мають бути впритул до рекламного блоку (випадкові кліки).
- Прелоад interstitial, щоб не з’являвся із запізненням після переходу.

### 3.3 Рекомендована модель для читача документів (ПРИПУЩЕННЯ/пропозиція, не вимога політики)
- Дозволено: **адаптивний банер** на екрані списку «Останні»/інструментів (не в режимі читання); **interstitial** лише після завершення «вагомої» дії (злито/розділено/збережено файл), з обмеженням частоти (напр. не частіше 1 на N хв).
- Заборонено нами: реклама при відкритті файлу, над кнопками керування/панеллю анотацій, під час читання/малювання, App Open ad.
- Рекомендація щодо `native`-реклами у списку файлів — можна, з чіткою позначкою «Реклама».
- **Офлайн:** реклама просто не показується; інтерфейс не повинен залишати порожнє місце-«діру» (згорнути контейнер). Читання/редагування працює без мережі.
- **«Без реклами» як платна опція** — лише опис: разова покупка або підписка через Play Billing; потребує інтеграції Billing, політики повернення, змінює Data safety/торгову позицію. **Рішення не пропоную.**

### 3.4 GDPR/EEA, UMP, політика конфіденційності
- Для користувачів ЄЕЗ/Великої Британії потрібна згода через сертифіковану CMP; Google пропонує **UMP SDK** (локально зберігає стан згоди) [З ЗВЕДЕННЯ ПОШУКУ]. Реклама **не завантажується до отримання згоди** (де вона потрібна).
- **Політика конфіденційності** — обов’язкова, публічне посилання в Play Console та в застосунку; має згадувати AdMob, IP/рекламний ID.
- **Data safety (що заповнювати з AdMob)** [З ЗВЕДЕННЯ ПОШУКУ; офіційний перелік AdMob «Play Data disclosure» — **відкрити й звірити**]:  
  Collected+Shared: приблизне місцезнаходження (IP), взаємодії з продуктом, діагностика/логи збоїв, ідентифікатори пристрою/реклами. Мета: реклама, аналітика, запобігання шахрайству. Шифрування під час передачі — так. Видалення даних — залежить від власного бекенду (його немає).
- **INTERNET** — потрібен лише для реклами (і оновлень/IAP). Сам читач працює без нього. Варіант: платна версія без реклами **без** INTERNET (ПРИПУЩЕННЯ).
- Увага: «Families»-політика — якщо застосунок націлений на дітей, реклама сильно обмежена; рекомендація — **не** орієнтувати на дітей (вікова цільова ≥ 18/13+ за вибором; рішення власника).

## 7. Пропозиція MVP

**Етапи (послідовність, складність):**
0. Каркас: проєкт, CI, SAF-відкриття, список «Останні» (S–M).
1. Перегляд: рендер, прокрутка, масштаб, перехід на сторінку, пароль при відкритті (M–L).
2. Пошук, закладки, мініатюри, нічний режим (M).
3. Інструменти: злиття, розділення, поворот, видалення/перестановка, зображення→PDF (M–L).
4. Реклама + UMP + політика конфіденційності + Data safety (M).
5. Закрите тестування Google Play (≥14 днів) — паралельно з 3–4 (потрібно 12+ людей; **дії власника**).
6. Анотації (виділення/малювання/текст) — після першого релізу (L).
Не в MVP: OCR, редагування тексту, форми, стиснення, юридично значимий підпис.

**minSdk:** рекомендація **26 (Android 8.0)** як компроміс — ПРИПУЩЕННЯ. Частки пристроїв я **не перевіряв** (потрібна свіжа статистика Android dashboard — НЕ ПЕРЕВІРЕНО). Якщо ставити лише на платформний рендер — minSdk 31; тоді відсікаються старі телефони. Рішення залежить від варіанта рушія (розд. 1.2).

**Цілі продуктивності (пропозиції, ПРИПУЩЕННЯ):** холодний старт ≤ 2 с; перша сторінка ≤ 1 с для файлу до 20 МБ; прокрутка 60 fps; пам’ять піку ≤ 250 МБ для 500-сторінкового файлу; AAB-розмір ≤ 25 МБ на ABI без реклами (виміряти на прототипі); crash-free ≥ 99,5 %.
