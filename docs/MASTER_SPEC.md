# MASTER_SPEC — PDF Reader для Android
Версія: v0.0 (чернетка). Веде лише Керівник проєкту.

## Статус
Фаза 1 (реалізація MVP). Розширення v0.4: розміщення тексту, ✓/✗ і полів на сторінці (див. R9–R12).

## Ціль
Android-застосунок для читання й роботи з PDF, монетизація рекламою, публікація в Google Play.

## Склад MVP (Phase 1)
1. **Модуль перегляду (`core-pdf` + `app`):**
   - Відкриття PDF через Storage Access Framework (SAF) та через системний намір «Відкрити за допомогою...» (`ACTION_VIEW`).
   - Перегляд сторінок, безшовна вертикальна прокрутка, плавний жест масштабування (pinch-to-zoom).
   - Посторінковий пошук тексту та виділення тексту (для Android 12+ на системному API, для Android 9..11 — інформативне повідомлення).
   - Відкриття документів, захищених паролем (діалог введення пароля).
2. **Менеджер документів (`app`):**
   - Екран списку «Останні документи» (локальна база Room, збереження метаданих: імʼя, розмір, дата, кількість сторінок, остання відкрита сторінка).
   - Закладки для швидкого доступу до обраних сторінок.
   - Повністю офлайн-робота з файлами. Файли не залишають пристрій.
3. **Набір інструментів сторінок (`core-pdf`):**
   - Злиття (Merge) двох або більше PDF в один.
   - Розділення (Split) PDF (вилучення діапазону сторінок або по окремих файлах).
   - Поворот сторінок (90°, 180°, 270°).
   - Видалення та перестановка сторінок з мініатюрами.
   - Конвертація «Зображення в PDF».
4. **Монетизація та приватність (`core-ads`):**
   - Показ форми згоди UMP (GDPR) перед завантаженням реклами.
   - Адаптивний банер у списку останніх та на екрані інструментів.
   - Interstitial (повноекранна реклама) виключно після збереження результату інструментів (не частіше 1 разу на 5 хвилин).
   - Коректна поведінка офлайн (згортання рекламних контейнерів без пустих місць).

5. **Розміщення на сторінці (v0.4):** текст, ✓/✗, малювання, підпис; заповнення полів AcroForm; єдине збереження (CONTRACTS §1.5).

## Незмінні правила
- Усі ліцензії сумісні із закритою комерційною публікацією, якщо власник не вирішив інакше.
- Доступ до файлів лише через SAF; MANAGE_EXTERNAL_STORAGE тільки за обовʼязкової потреби й рішення власника.
- Жодної аналітики й збору даних понад необхідне для реклами та без згоди. Файли користувача не покидають телефон без явної згоди.
- Секрети (ключі підпису, паролі, токени) ніколи не в репозиторії чи чаті.
- Платна дія спершу власнику з точною сумою й альтернативою.
- `@ExperimentalPdfApi` дозволено лише в одному класі-обгортці. Критичні правки геометрії координат перевіряє агент, що не писав код.
- Етапи розміщення на сторінці виконуються послідовно: 1a, Етап 0 (спайк-2), 1b, 2, 3, 4. 1b, 2, 3, 4 не починаються, доки гейт Етапу 0 не пройдено або власник не схвалив варіант B. Порядок і гілки: `docs/research/MARKUP_STAGES.md`.

Керівник проєкту; PDF-ядро; Android і UI; Монетизація і Google Play; QA і безпека (+ ролі за потреби).

## Процес
Гілки `feature/...`, пуш/PR/злиття лише власник. Паралельно лише через git worktree. Кожен агент завершує підсумком: Що зроблено / Що змінено / Рішення / Що передати далі / Відкриті питання.

## Якість
Бюджети продуктивності (час відкриття, памʼять, сторінки на великих файлах) на release-збірці на реальному телефоні (Galaxy S24 Ultra). Тести: сотні сторінок, скановані, зашифровані, пошкоджені, поворот, завершення процесу. Критичні висновки перевіряє агент, що не писав код.
