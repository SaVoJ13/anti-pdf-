# QA-промт: рамка тексту біля правого краю (гілка `fix/text-box-overhang`)

Ти незалежний QA (не автор). Прочитай `docs/governance/CONSTITUTION.uk.md`, `PROJECT_PROFILE.md`, `CURRENT_STATE.md`, `LESSONS.md`, `docs/qa/QA_selection-pill_2026-11-17.md` (розд. «Дефекти», п. 1). Правила пристрою, збірка й формат звіту як у `docs/qa/QA_PROMPT_selection-pill.md`. Не став `QA Verified`, якщо кроки 1-3 не пройдені на телефоні.

## Що змінено
`PlaceMarkupLogic.fitAnchorXForText` + виклики в `ReaderActivity` («Змінити текст» і слайдер розміру тексту): якщо найдовше слово не влазить у залишок сторінки, рамку зсувають ліворуч рівно настільки, щоб слово вмістилося ціле. Раніше слово розбивалось по літерах («ALPH / A / BETA»). Причина: `clampToPage` обмежує лише лівий верхній кут, рамка могла виходити за край, а перенос рахується від залишку сторінки (`maxTextLineWidthPt`).

## Сценарії (режим «Редагувати», елементи не зберігати, якщо не сказано)
1. **Відтворення з QA PR #8:** текст `ALPHA`, потягнути ручку розміру до ≈100 pt, перетягнути вправо так, щоб рамка заходила за край; «Змінити текст», дописати Enter + `BETA`, підтвердити. Очікується: «ALPHA / BETA» цілими словами, рамка зсунулась ліворуч, у межах сторінки.
2. Те саме зі слайдером розміру (картка параметрів, виділений текст біля правого краю, збільшити розмір): слово не ламається по літерах.
3. **Без побічних змін:** текст посередині сторінки: «Змінити текст» не зсуває рамку; довгий абзац переноситься як раніше; Enter зберігається (два рядки, також у збереженому файлі).
4. Ландшафт → портрет після «Змінити текст» (спостереження (а) PR #7): рамка не звужується.
5. Повторити кроки 11-12 з `QA_PROMPT_selection-pill.md` (чернетка редагована після «Порожня сторінка», Enter).
6. Збірка, `:app` і `:core-pdf` тести, lint за XML (очікується `:app` 403/0/0/0, `:core-pdf` 214 записів 0/0/2 пропущено, lint 0 помилок).
