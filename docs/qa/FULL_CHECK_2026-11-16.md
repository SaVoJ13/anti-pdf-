## Список дефектів
Критичних немає.

**Д1 (середня). `font_scale` при відкритому вікні тексту знищує введений текст і лишає витік вікна.**
Кроки: відкрити PDF → «Редагувати» → інструмент «Текст» → тап по сторінці → ввести текст → змінити розмір шрифту системи (`adb shell settings put system font_scale 1.3` або в Налаштуваннях) без підтвердження. Результат: вікно тексту зникає, введений текст втрачено, у logcat `WindowLeaked ... ReaderActivity`. Те саме з відкритою карткою пера (картка закривається, інструмент лишається). Причина: у маніфесті `configChanges` має `orientation|screenSize|screenLayout|smallestScreenSize`, але не `fontScale`, тому застосунок перестворюється; а вікно тексту створено як звичайний `Dialog` в `ReaderActivity.kt` (блок `showPlaceTextDialog`, ~рядки 1085–1884) і не зберігає/не відновлює введений текст і позицію поля. Орієнтація тут безпечна (є `configChanges`). Рекомендація: додати `fontScale` у `configChanges` або зберігати текст/стан у ViewModel.

**Д2 (низька). Збереження, коли файл відкрито з іншого застосунку лише на читання, показує сиру помилку.**
Кроки: `am start -a VIEW -d content://... -t application/pdf -f 1` (лише читання) → «Редагувати» → додати текст → «Зберегти». Результат: діалог «Помилка збереження розмітки: com.savoj.volumpdf.anti has no access to content://media/external/file/...». Очікувано: пропозиція «Зберегти копію». Місце: шлях збереження `savePending()` у `ReaderActivity.kt` (~рядок 1890+), мапінг помилок доступу. Помітка: це може бути лише синтетичним випадком (реальні застосунки видають часом тільки читання), тому перевірити з типовим файловим менеджером.

**Д3 (низька). Ландшафт із клавіатурою: поле тексту частково перекрите панеллю-пігулкою.**
